# Incumbents as executed arms

Converting "incumbents were read, not executed" into a measurement wherever no paid credential is
required, and stating the exact blocker where one is.

Frozen corpora this report is stated against:

| Corpus | content SHA256 | Used for |
|---|---|---|
| `data/corpus/synthetic` | `25c2953a0b38dc4066e8cff99f01aa3cbd39aca6296018966b57fbde34d24ebb` | disambiguation arms |
| `data/corpus/relations` | `aba780bd15ffeb303b065b1812c0f716e75397cae99112ad73b81ee2197b6e6d` | write-path probes |

Both hashes were recomputed from disk after the last run and are unchanged. Nothing under
`data/corpus/` was written to.

**Result in one line.** Nine configurations ran, none was blocked on a credential, and the paper's
third-branch claim holds in every one of them: on 60 labelled distinct-event pairs, no system records
a relation that survives, the store state after keeping both is structurally identical to the state
after an unrelated write, and Mem0 0.1.118's real write path under a 0.85 similarity policy destroys
33.33% [22.50, 43.75] of those pairs.

### 1.2 What is measured

Four quantities. The first three are write-path quantities and are the point of the exercise; the
fourth is the retrieval number that makes an incumbent comparable to the existing arm table.

**(D) Distinct-event destruction rate.** Over the INTERFERENCE pairs of the frozen relational corpus
(`cls == "INTERFERENCE"`, the class whose action map entry is *keep both, mark siblings, never
merge*): write episode `a`, then episode `b`, into a fresh store through the system's real write
path, then inspect the store.

D = #{pairs where at least one of a, b is no longer separately addressable} / #pairs

"Separately addressable" means a stored record exists that is attributable to that source episode
and is not the same record as the other episode's. Destruction covers both the merge outcome (one
record absorbs the other) and the invalidate outcome (one record is expired or deleted). Reported
per regime (short, long) and pooled, with a BCa bootstrap interval resampling on `cluster_id`,
alpha = 0.05, 10000 resamples, using `brain.eval.bootstrap.cluster_bootstrap_ci` so the interval is
computed by the same code as every other interval in this project.

**(E) Third-branch expressiveness.** Over the same INTERFERENCE pairs, under an *oracle* judge (see
1.3):

E = #{pairs whose persisted store state contains a field that links the two records and is absent
from the matched control} / #pairs

The matched control for pair (a, b) is (a, c) where c is a deterministically chosen episode from a
different cluster, i.e. a genuinely unrelated write. A field only counts if it distinguishes the
confusable case from the unrelated case; a field that is present in both records nothing about
confusability.

**Pre-registered prediction: E = 0 for every system measured.** This is the paper's third-branch
claim, and E > 0 for any system falsifies it.

**(I) Residual indistinguishability.** Over the same pairs:

I = #{pairs whose canonical structural signature after writing (a, b) equals the signature after
writing the matched control (a, c)} / #pairs

The structural signature is content-blind by construction: record count, the sorted set of field
names per record, which fields are non-null, the set of edge or link types, and the temporal
validity flags. Content is excluded because the two situations differ in content by construction;
the claim under test is that nothing *structural* separates them.

**Pre-registered prediction: I = 1 for every system measured.**

**(A) Disambiguation accuracy** on the frozen synthetic corpus (120 episodes, 360 queries, 33
clusters, SHA `25c2953a...`) through `brain.eval.runner.run_arm`, k = 5, seeds (0, 1, 2, 3, 4),
cluster-level BCa interval, identical to every arm already in the table. Reported only for a system
whose retrieval path can be driven end to end without a credential.

### 1.3 Judges, declared in advance

Every system under test calls an LLM inside its write path. No credential is available, so the LLM
is substituted, and the substitution is stated on every number. Three judges, fixed before any run:

| Judge | Definition | What it isolates |
|---|---|---|
| `identity` | one memory per episode, text passed through unchanged, always the system's additive/create operation | the system's storage and retrieval layer with no rewriting |
| `oracle` | ground-truth-aware and maximally preserving: it is told the pair is distinct, never emits a merge or an invalidate, and additionally emits the relation in every schema field the system's own prompt or response model defines | the ceiling. What the system can express when the judge is perfect |
| `tau085` | no ground truth. Cosine similarity between the new text and each retrieved memory under the project embedder; above 0.85 it emits the system's merge/supersede operation, below it emits create. 0.85 is F17's threshold, carried over unchanged | a realistic similarity policy, comparable to F17 |

The oracle judge is the load-bearing one. A number measured under a judge that is *trying* to keep
both and *trying* to record the relation is an upper bound on the system's architecture, so a
failure under it is architectural and cannot be blamed on model quality.

Where a system's response schema is small enough to enumerate, the judge is replaced by
**exhaustive enumeration of the response space**, which removes the judge from the argument
entirely. This is pre-registered as the preferred method wherever it applies.

### 1.4 Analysis rules

- No metric is redefined after a number is seen. A metric that turns out to be ill-posed is reported
  as ill-posed, with the reason, and not replaced by a more flattering one.
- Numbers we did not produce are never mixed with numbers we did. Published figures live in their
  own section, labelled, with a paper and table reference.
- No number is estimated, interpolated, or inferred for a system that did not run.
- The frozen corpus hashes are asserted at the end of the run and recorded in the JSON.

*Sections 2 onward are written after the runs and record what happened.*

## 2. The measured rates

Three write-path rates over the 60 INTERFERENCE pairs of the frozen relational corpus, each pair
against a matched cross-cluster control, with cluster-level BCa intervals computed by
`brain.eval.bootstrap.cluster_bootstrap_ci`, alpha 0.05, 10000 resamples, resampling on
`cluster_id`, exactly as every other interval in this project.

**The headline. Mem0 0.1.118's real write path, driven by a similarity policy at tau = 0.85,
destroys 20 of 60 distinct-event pairs, 0.3333 [0.2250, 0.4375].** Split by regime it is 0.6667
[0.4483, 0.8780] on session notes and 0.0000 on terse assertions. F17 measured 36.57% for this
project's own merge baseline at the same threshold; running the same policy through a shipped
system's actual `_update_memory` gives 33.33%, inside F17's interval. The threshold is ours and is
labelled as ours; what is not ours is the code that executed the destruction.

**And the third branch is absent in every configuration.** E is 0 of 60 everywhere except Mem0
2.0.15, where it is 8 of 60 under BOTH judges. The identity judge asserts no relation at all and the
oracle judge asserts five, and they produce the same 8, which is what proves those eight links are
entity co-mention derived from the text rather than a record of any decision. Nothing the oracle

**Reading the table.**

- **Nous's row is not a result about its architecture and must not be read as one.** Its
  `neighbour offered` is 0 of 60 because its rule-based extractor produced 0 claims on this corpus,
  so its belief layer never engaged and there was no decision point at all. Its `I` of 42 of 60 is
  content-derived too: the evidence record carries extracted `entities` and `terms`, and whether
  those are empty varies with the text. Section 4.3 puts the same question to Nous in its own
  domain, where its belief layer does engage.
- **`I` and `D` are not independent under a destroying judge.** For `mem0-0.1.118-tau085`, the 20
  destroyed pairs leave one record where the control leaves two, so they are trivially
  distinguishable from the control by count; the 40 surviving pairs are indistinguishable in all 40.
  Read `I` as: conditional on keeping both, nothing structural separates a confusable pair from an
  unrelated one, in 40 of 40.
- **`E` is the only rate where a non-zero value would falsify the paper**, and the two Mem0 2.0.15
  rows are the only non-zero ones. The identity-versus-oracle equality is what settles their reading.

## 3. Method: what was substituted, and what was not

| System | LLM | Embedder | Store | Substituted? |
|---|---|---|---|---|
| Mem0 2.0.15 | judge stub in a claimed provider slot | sentence-transformers all-MiniLM-L6-v2, the project's own | faiss on a local path, sqlite3 history | LLM only |
| Mem0 0.1.118 | judge stub, same mechanism | same | same | LLM only |
| Graphiti 0.29.2 | none needed: the branch set is enumerated | none needed | none needed | nothing; no model is involved |
| TOKI | none needed: the contradiction test is closed form | none | DuckDB in memory | nothing |
| Nous 0.2.0 | none needed: the shipped extractor is rule-based | none | stdlib sqlite3 | nothing |

Three of the five run with no substitution at all. Only Mem0 needs one, because Mem0 constructs an
LLM client eagerly in `Memory.__init__` and raises `openai.OpenAIError` without `OPENAI_API_KEY`, and
because its `LlmFactory.register_provider` cannot actually be used: `LlmConfig.validate_config`
checks the provider name against a hard-coded tuple inside a function body, so a new name is
rejected before the factory is consulted. An existing slot is claimed instead, and which one is
recorded in the result file. Mem0's prompt building and its response parsing are untouched.

Telemetry is disabled for every Mem0 run. `MEM0_TELEMETRY` defaults to `True` and posts to PostHog,
so a probe that did not disable it would not be offline.

**Prior art for this method, and it is close.** TOKI ships exactly this technique: a
`DeterministicJudge` that stands in for the LLM in the contradiction path of Mem0 v2, Mem0 v3,
Graphiti and WorldDB, at pinned commits, so their real write paths can be executed without a key
(`experiments/anomaly_wire/adapter_base.py`, mem0 pinned at
`a623cfaf76ae7379a58be1e837f8a88a9b15a184`). Anything this report claims about the technique itself
is theirs, not ours. What differs is the judge and the quantity: TOKI's stub votes by hashing the
prompt, which is an arbitrary judge, whereas the judge that matters here is an ORACLE, the most
preserving judge the schema admits. An arbitrary judge confounds model behaviour with architecture;
an oracle judge upper-bounds the architecture, which is what a claim about branch sets requires.

## 4. The exhaustive probes

These three do not sample. Each system's decision space is finite and every element of it was
executed, so the result quantifies over all possible model outputs rather than over a sample.

### 4.1 Graphiti 0.29.2, the whole response space of `resolve_extracted_edge`

`resolve_extracted_edge` decides what happens to a fact that collides with an existing one, from a
single structured response whose model is `EdgeDuplicate`: two integer lists, `duplicate_facts` and
`contradicted_facts`, and nothing else. With one duplicate candidate and one invalidation candidate
in context the space has eight elements. All eight were executed under two temporal shapes,
sixteen executions, with no database, no key and no network, because the function takes its
candidate edges as plain arguments and never touches a driver.

| Shape | duplicate_facts | contradicted_facts | identical to the no-candidate control | duplicates | invalidated |
|---|---|---|---|---|---|
| supersession | [] | [] | **yes** | 0 | 0 |
| supersession | [] | [0] | no | 0 | 1 |
| supersession | [] | [1] | no | 0 | 1 |
| supersession | [] | [0, 1] | no | 0 | 2 |
| supersession | [0] | any of the four | no | 1 | 0 |
| interference | [] | [] | **yes** | 0 | 0 |
| interference | [] | [0] | **yes** | 0 | 0 |
| interference | [] | [1] | **yes** | 0 | 0 |
| interference | [] | [0, 1] | **yes** | 0 | 0 |
| interference | [0] | any of the four | no | 1 | 0 |

Three things follow, and all three are executed rather than read.

1. **The keep-both response is byte-identical to never having seen the neighbour.** The returned
   `(resolved, invalidated, duplicates)` triple for "a confusable neighbour was examined and
   deliberately kept apart" serialises identically to the triple returned when no candidate edge
   exists at all. Nothing in the return value, and therefore nothing in what is persisted,
   distinguishes them. The paper's claim, previously an audit, is now a measurement.
2. **For contemporaneous facts the invalidate branch is a silent no-op.** In the interference shape,
   where the two facts are valid at the same time, asserting a contradiction changes nothing: 4 of
   the 8 responses return the control triple, including every response that says the facts
   contradict. Graphiti's invalidation is time-ordered, so a contradiction between two facts that
   overlap in valid time cannot fire. The two-branch write collapses to one branch exactly in the
   regime the interference corpus is about. This was not visible from the source read.
3. **The response model cannot carry a third instruction.** `EdgeDuplicate` has exactly two fields.
   Responses carrying `sibling_facts`, `keep_both`, `distinct_facts` or `relation` are accepted by
   the parser without error and **none of those fields survives it**: the count that survived was 0
   in all three probes. `EntityEdge` has fourteen fields, `attributes`, `created_at`, `episodes`,
   `expired_at`, `fact`, `fact_embedding`, `group_id`, `invalid_at`, `name`, `reference_time`,
   `source_node_uuid`, `target_node_uuid`, `uuid`, `valid_at`, and not one of them can hold a
   sibling or a forward supersession link.

### 4.2 TOKI, the whole resolution algebra

TOKI's contradiction test is closed form and needs no model at all
(`bitemporal/operators.py:is_contradiction`): subject equal, predicate equal, object different, and
the closed-open valid-time periods overlap. So the write path is characterised completely by
executing all four operators (`lww`, `evi`, `await`, `rule`) over the three arrangements a pair of
episodes can take, twelve executions on in-memory DuckDB with no key and no server.

| Arrangement | contradiction | resolution fired | current rows | both open | audit rows |
|---|---|---|---|---|---|
| same key, overlapping validity | **yes** | yes, under all four operators | 1 | **no** | 1 |
| same key, disjoint validity | no | no | 2 | yes | 0 |
| different key | no | no | 2 | yes | 0 |

- **A contemporaneous distinct-event pair is destroyed under every operator, 4 of 4.** Two events
  that share a key and overlap in time are a contradiction by definition, and one row is closed.
  The predicate cannot tell "the value changed" from "two different things happened".
- **TOKI is the only system in the set that leaves a trace when it destroys.** An audit row is
  written on every resolution, which is its own N3 defence, and it is a real difference from
  Graphiti, where the loser is expired and nothing points to what replaced it.
- **But keeping both is still the null residual.** When the pair does not overlap in time, both rows
  stay open and the resulting state is structurally identical to two entirely unrelated writes: same
  row count, same audit count, same columns. There is no third branch here either.

This is consistent with TOKI's own framing rather than a deficiency found by us: the paper names
embedding-similarity matching as an open problem and matches on exact keys.

### 4.3 Nous 0.2.0, run with nothing substituted

Nous needs no credential: zero declared runtime dependencies, stdlib sqlite3, and a rule-based
extractor. It is the only arm here measured with its own components end to end.

**On the frozen corpus its extractor yields nothing.** Across the interference pairs it extracted 0
claims, wrote 0 belief dimensions and 0 deltas, and recorded only the raw text in `evidence_events`.
That is a domain mismatch, not a result about its architecture: the extractor targets conversational
personal facts and the corpus is engineering session notes. Reporting a destruction rate of 0 from
that would be reporting that the system never ran.

**So it was put the same question in its own domain**, in its README's idiom, and there the belief
layer engages and answers clearly:

| Case | dimensions | posterior |
|---|---|---|
| two facts BOTH true, same dimension | 1 | `Pranav.employer` = {IIT Ropar 0.857, Google DeepMind 0.117, unknown 0.026} |
| two unrelated facts | 2 | each 0.818 on its own value |

**Nous converts interference into contradiction by construction.** Two facts that are both true and
land on the same `entity.attribute` become competing values of one variable, and the second drives
the first from 0.818 down to 0.117. The evidence layer keeps both texts verbatim, so nothing is
erased, but the belief layer now asserts that one of two true things is probably false. That is a
third form of the same gap: not a merge, not an invalidate, but a keep-both-as-alternatives where
what was needed was keep-both-as-coexisting.

One honest caveat travels with the supersession case: the rule-based extractor read "Pranav now
works at OpenAI" as an entity named `Pranav now`, so the supersession never reached the same
dimension. The extractor is brittle, and that is visible in the paper's own Table 3 failure buckets.

### The two BLOCKED items, stated exactly

**Graphiti end to end is BLOCKED on an embedder, not on the LLM.** A local LLM could be reached
through `OpenAIGenericClient` against an OpenAI-compatible daemon, but `graphiti_core.embedder`
ships only `OpenAIEmbedder`, `AzureOpenAIEmbedderClient`, `GeminiEmbedder` and `VoyageAIEmbedder`,
all of which call a hosted API. Running Graphiti end to end here would require either a paid
embedding key or a local OpenAI-compatible embedding daemon, and no such daemon is installed on this
machine (no Ollama, no Docker). The store is a second blocker of a different kind: the only
serverless driver, Kuzu, is deprecated in this version with a warning on every construction, so a
number measured on it would be measured on a path the maintainers are removing.
**What it would take:** `pip install "graphiti-core[kuzu]"`, plus a local OpenAI-compatible endpoint
serving both a chat model and an embedding model, plus acceptance of the deprecated driver.

**TOKI's cross-system anomaly-wire sweep is BLOCKED on two local dependencies**, not on a key:
`sqlalchemy`, imported by its Letta adapter at module load, and a pinned Mem0 clone at
`a623cfaf76ae7379a58be1e837f8a88a9b15a184` under `references/repos/mem0`. Its own bitemporal core is
not blocked and was run: **308 tests pass** with no key and no server.

Nothing here was blocked on a credential we chose not to buy. No credential was obtained, requested,
or used.

seen; the file's first commit is the pre-registration alone.

1. **`tau085` was not run against Mem0 2.0.15.** It is not applicable: the additive response schema
   that version ships has exactly one operation, so there is no merge or invalidate for a threshold
   policy to emit. This is reported as a structural finding, not as a missing run.
2. **For Graphiti and TOKI, enumeration replaced sampling.** Section 1.3 pre-registered exhaustive
   enumeration as the preferred method wherever the response space is small enough, so this is
   within the plan, but the consequence must be read correctly: D, E and I for those two systems are
   not rates over 60 pairs and carry no bootstrap interval. They are exhaustive facts about a
   decision space, which is a stronger statement over a narrower object.
3. **Nous's in-domain probe is post-hoc, and is labelled as such.** It was added after observing
   that Nous extracted 0 claims from the frozen corpus. The alternative was to report a destruction
   rate of 0 for a system whose belief layer never ran, which would have been true and misleading.
   The frozen-corpus result is reported alongside it, unchanged.
4. **E is reported under `identity` as well as under `oracle`**, although Section 1.2 defines it
   under `oracle` only. The identity arm is the control that decides how to read a non-zero E: the
   identity judge asserts no relation at all, so any link it produces cannot be a response to a
   relation claim.
5. **TOKI and Nous turned out to be runnable.** The pre-registration left their code availability
   open and provided for a BLOCKED verdict. Neither needed one.
6. **The mem0 branch enumeration and the TOKI probe were appended to the result file after the main
   run started**, because both were written while the Mem0 pair runs were executing. They are the
   same corpus, the same code and the same session; the append is recorded in the JSON.

## 7. What this changes for the paper

The paper's third-branch claim was an audit: every shipped system has a two-branch write, merge or
invalidate, with a silent fall-through, and none has an affirmative "these are distinct, keep both,
mark as siblings" operation that leaves a trace. It is now a measurement, on four systems, with no
credential involved, and the measurement is sharper than the audit in seven specific ways.

**1. The claim survives, and it survives under an oracle.** For Mem0 2.0.15 the oracle judge asserts
five relation fields on every write, including Mem0's own `linked_memory_ids` populated with the real
UUID of the neighbour. `attributed_to`, a field Mem0 does read, survives into the persisted payload,
so the response was parsed. **None of the five relation fields survives.** The identity judge, which
asserts nothing at all, produces exactly the same number of distinguishing links, 8 of 60 against 8
of 60, which proves those eight are entity co-mention derived from the text rather than a record of
any decision. The oracle contributed zero. That is the strongest form the claim can take: not "a
model failed to record the relation" but "the most preserving judge the schema admits cannot".

**2. Mem0 2.0.15 no longer has a two-branch write at all. It has one branch.** The
`ADD`/`UPDATE`/`DELETE`/`NONE` dispatcher is gone from the write path; `get_update_memory_messages`
and `DEFAULT_UPDATE_MEMORY_PROMPT` are still in the package and are called from nowhere in it. The
v3 additive path only inserts, deduplicating on an exact md5 of the memory text. Measured
consequence: **destruction 0 of 60**. The paper should say two-branch of the version it audits, and
say that the current release removed the second branch rather than adding a third.

**3. The silent fall-through is literally an absent `else`, and it costs the write.** Executing the
whole event space of Mem0 0.1.118 on one interference pair:

| `event` | memories after | episodes still addressable | link recorded |
|---|---|---|---|
| `ADD` | 2 | both | none |
| `UPDATE` | 1 | the new one only | none |
| `DELETE` | 0 | neither | none |
| `NONE` | 1 | the old one only | none |
| `LINK` (invented) | 1 | the old one only | none |
| `SIBLING` (invented) | 1 | the old one only | none |

An operation the dispatcher does not know is not rejected and does not raise. It falls through to
nothing, byte-identical to `NONE`, and **the incoming episode is lost**. So the cost of there being
no third branch is not merely that the relation goes unrecorded; a system that tried to emit one
would silently drop the write.

**4. Graphiti's invalidate branch is a no-op exactly where interference lives.** This was not visible
from source reading. Graphiti's invalidation is ordered by valid time, so for two facts valid at the
same time, asserting a contradiction produces a return triple byte-identical to never having seen
the neighbour. In the contemporaneous shape, 4 of the 8 possible responses collapse to the control,
including every response that says the facts contradict. The two-branch write is a one-branch write
for contemporaneous facts, which is the regime the interference corpus is about.

**5. The gap has three distinct shapes across the four systems, not one.** The paper currently
describes one gap. What was measured is:

| System | What happens to a confusable distinct pair | What is missing |
|---|---|---|
| Mem0 2.0.15 | both kept, always | any record that they were compared |
| Mem0 0.1.118 | merge, invalidate, drop, or keep, at the judge's discretion | any operation that keeps both AND records why |
| Graphiti 0.29.2 | merged, invalidated, or kept with a return value identical to an unrelated write | the third branch, and the forward link |
| TOKI | destroyed under all four operators when contemporaneous, with an audit row | a way to tell "the value changed" from "two things happened" |
| Nous 0.2.0 | both texts kept, but the belief layer scores them as competing values of one variable | coexistence; interference becomes contradiction by construction |

TOKI is the one system that leaves a trace when it destroys, and that difference should be credited
in the paper rather than flattened into the general claim.

**6. The destruction rate is now a number from a shipped system, not from our merge baseline.**
Mem0 0.1.118's real write path under a similarity policy at the same tau = 0.85 destroys 33.33% of
distinct-event pairs, [0.2250, 0.4375], against F17's 36.57% for this project's own baseline. That
is an independent replication of F17 inside somebody else's code, and it splits by regime the same
way the rest of this project does: 66.67% on session notes, 0% on terse assertions.

**7. And Mem0's retrieval layer measures exactly plain_vector.** 0.6194 [0.5273, 0.6812] on the
frozen corpus, agreeing with `plain_vector` on all four metrics to four decimals and on both
interval bounds to ten. The paper can now say that the incumbent it compares against is, on the
retrieval axis and with rewriting removed, the same arm the paper already reports, and that it
loses to BM25 and to full context by the same margins.

**And one correction the paper must carry.** The graveyard records that Mem0's `linked_memory_ids`
"is never persisted in the OSS code". That is now half wrong for 2.0.15: a memory-to-memory link IS
persisted, in the entity store, where each extracted entity carries the ids of the memories that
mention it. It is not what the audit meant, since it records co-mention rather than a decision, and
the identity-versus-oracle contrast proves that, but the sentence as written is false of the current
release and should be narrowed to the LLM-emitted field on the memory record.
7. **One worker process was terminated after it had written its output.** Every Mem0 instance leaves
   faiss and OpenMP thread pools behind and never releases them, so a configuration over 120 stores
   ends with several hundred live threads and normal interpreter shutdown spends longer joining them
   than the probe spent measuring. The `mem0-0.1.118-identity` child was sent SIGTERM after its
   output file was complete and valid, and the worker now exits with `os._exit` so later
   configurations do not hit the same tail. No measurement is affected: the result file is written
   and closed before the exit path is reached, and the JSON was parsed and checked before the signal
   was sent.

## Appendix A. How to reproduce

Each incumbent lives in its own virtual environment, because their dependency stacks are mutually
incompatible with this project's pinned one (Mem0 2.0.15 pulls numpy 2, this project is pinned below
it). The environments are named to the runner through four variables, and the exact resolved
versions are recorded in the result JSON under `configurations[].venv.packages`.

```sh
python3 -m venv venv-mem0        && venv-mem0/bin/pip install "mem0ai==2.0.15" \
                                       sentence-transformers faiss-cpu spacy
venv-mem0/bin/python -m spacy download en_core_web_sm     # entity linking is a no-op without it
python3 -m venv venv-mem0-legacy && venv-mem0-legacy/bin/pip install "mem0ai==0.1.118" \
                                       sentence-transformers faiss-cpu
python3 -m venv venv-graphiti    && venv-graphiti/bin/pip install "graphiti-core==0.29.2"
python3 -m venv venv-nous        && venv-nous/bin/pip install "nous-state==0.2.0"
git clone https://github.com/ZhoeMrety/toki-bitemporal-memory toki
python3 -m venv venv-toki        && venv-toki/bin/pip install -e "toki[test,experiments]"

export BRAIN_INCUMBENT_VENV_MEM0=$PWD/venv-mem0
export BRAIN_INCUMBENT_VENV_MEM0_LEGACY=$PWD/venv-mem0-legacy
export BRAIN_INCUMBENT_VENV_GRAPHITI=$PWD/venv-graphiti
export BRAIN_INCUMBENT_VENV_NOUS=$PWD/venv-nous
export BRAIN_INCUMBENT_VENV_TOKI=$PWD/venv-toki

python -m brain.baselines.incumbents                    # the write-path probes
python -m brain.baselines.incumbents.run_arm            # Mem0 as a scored retrieval arm
python -m brain.baselines.incumbents.report results/incumbents-<stamp>.json
pytest tests/test_incumbents.py
```

No step requires a credential. `pip install` reaches PyPI and the spaCy model download reaches
GitHub; everything after that runs offline, and `HF_HUB_OFFLINE=1` and `MEM0_TELEMETRY=False` are set
by the worker itself.

**The TOKI repository URL printed in its paper 404s.** The paper's first-page footnote gives
`github.com/ZenAlexa/toki-bitemporal-memory`, which does not resolve; the live mirror is the one
above. Cite the working URL.

**Note on the machine.** These runs shared a four-core host with other jobs, so wall-clock timings in
the result file measure contention, not the systems. Nothing else in the report depends on timing.
