# Does the crediting convention decide the sign on LoCoMo?

Pre-registered replication of the F23 crediting-convention finding on a public
benchmark. The machinery is unchanged; only the data is new.

## Pre-registration (fixed before any number was computed)

- **Benchmark**: LoCoMo-10 (Maharana et al., ACL 2024), commit `3eb6f2c585f5e1699204e3c3bdf7adc5c28cb376`, file sha256 `79fa87e90f040813...`
- **Shape**: 10 conversations, 5880 episodes (one per dialogue turn), 1527 queries, 272 sessions
- **Subset**: every conversation, every usable annotated question. No subsampling.
- **Thresholds**: 0.75, 0.8, 0.85, 0.9, 0.95, complete linkage, one pass per cell
- **Conventions**: credited, expected, strict (`credited` generous, `expected` = 1/(1+a), `strict` = nothing once a >= 1)
- **Primary cell**: destructive@0.85, depth @5, session-scoped distractors, resampled by conversation
- **Bootstrap**: paired BCa, 10000 resamples, cluster-level only

## Verdict

**IMMUNE** -- the three conventions coincide on almost every query; the lever cannot act

| convention | delta vs before (paired cluster BCa, 95%) |

| expected (`1/(1+a)`) | +0.007 [-0.002, +0.017] |
| strict | +0.007 [-0.002, +0.016] |

Fraction of queries on which all three conventions coincide: 0.9987.
